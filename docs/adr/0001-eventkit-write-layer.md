# ADR-0001：EventKit 作为唯一写入层

- 状态：已接受（2026-10-31）
- 关联：PRD §1/§4；NAN-120

## 背景

产品要求：无论哪种形态（agent / CLI / App），日程数据必须（1）在苹果官方日历与提醒事项中正确显示，（2）经 iCloud 同步到 iPhone。同时三形态共享一个核心模块，写入层必须稳定且可长期复用。

## 候选方案

| 方案 | 评估 |
|---|---|
| **EventKit**（官方框架，一套 API 读写日历+提醒事项） | 写入本地系统数据库，iCloud 自动同步；字段全（重复规则/提醒/备注/URL）；Swift 原生，与核心模块同语言 |
| AppleScript / JXA | 零构建，但慢、字段支持不全、中文转义易错；只适合临时摸底 |
| CalDAV 直连 iCloud | 需应用专用密码，走私有端点，脆弱且随时可能失效 |
| Shortcuts | 适合触发自动化，不适合作为程序化写入层 |

## 决策

`AppleToDoCore` 通过 EventKit 完成所有读写；**禁止**任何模块绕过它直接操作日历数据。写入目标限定为 iCloud 账户的日历/清单（具体目标见 ADR-0002）。最低平台 macOS 14（2026-11-04 修订：原为 13；EventKit 权限 API `requestFullAccessToEvents` 需 14+）。

## 后果

- 首次运行需用户授予日历/提醒事项权限（TCC 弹窗，一次授牌）
- CI 环境无法弹权限框 → 单测必须 mock，引出 ADR-0003
- 与苹果生态强绑定（符合本项目定位，视为特性而非负担）
