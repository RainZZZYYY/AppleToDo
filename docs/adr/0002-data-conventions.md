# ADR-0002：数据规范（日历/清单划分）

- 状态：暂行（2026-10-31，agent 代决；M1 实施时与 owner 盘点现有日历/清单后复核）
- 关联：NAN-121

## 背景

所有自动写入需要确定的落点。owner 未提供现有日历/清单清单，agent 按最小惊讶原则暂行决策。

## 决策

1. **日历事件**默认写入 iCloud 账户下名为 `AppleToDo` 的日历；不存在则创建；创建失败回退第一个可写的 iCloud 日历并告警。
2. **提醒事项**默认写入同名 `AppleToDo` 清单，回退策略同上。
3. **溯源标记**：自动创建的条目在备注首行附 `[AppleToDo]`，用于查重与审计；不修改标题，保持与手动创建条目观感一致。
4. **不触碰** owner 现有的个人日历/清单划分（工作/生活等）；AppleToDo 的产出隔离在自己的日历/清单内。
5. **修订（2026-11-04）**：第 1/2 条的「创建失败回退第一个可写 iCloud 日历并告警」调整为**显式报错**（`noWritableTarget`）——回退写入会触碰 owner 现有日历，与第 4 条冲突；报错把决策交还给调用方（agent/CLI）更安全。

## 后果

- owner 现有体系零污染；所有自动条目一眼可辨、一键可清（删除整个 AppleToDo 日历即可）
- 若 owner 希望直接写入现有日历（如「工作」），M1 时调整本规范即可
- `AppleToDo` 日历在 iPhone 上同步可见后，用户可自行调整显示颜色
