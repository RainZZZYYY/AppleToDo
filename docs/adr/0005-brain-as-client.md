# ADR-0005：大脑即客户——工具契约与适配器边界

- 状态：已接受（2026-11-04）
- 关联：PRD §1/§4/§5/§8；NAN-146；前置 ADR-0001/0003/0004

## 背景

owner 要求降低「大脑层」与其他层的耦合：未来可能把程序做成 MCP 类服务，Linear 也可能重写为插件。原 PRD 分层图把 LLM 画在流水线中间，隐含「程序内置大脑」的读法，需要明确反转。

## 决策

1. **大脑是外部客户，不是程序内部层。** 程序对外的本体是一组有清晰描述的能力（工具）；谁来调用——ZCode agent、任意 MCP 客户端、M6 的内置 LLM——对程序无感、可替换。
2. **能力契约按工具形状设计**（约束 Core 的 API 签名）：入参出参为 JSON 友好的值类型（Codable/Sendable）；错误作为数据返回（错误码化），不靠异常崩溃传达业务失败。
3. **适配器一律薄壳**：写入（EventKitStore）、信息源（LinearSource）、接口（CLI / MCP server / App UI）只做协议转换，不含业务规则；业务规则只在 Core。
4. **插件协议延迟抽象**：TaskSource 等插件接口在第二个真实实现出现前不预建，避免臆造接口（与 AGENTS.md 核心原则 2 一致）。
5. **M7 优先评估 Linear 官方 MCP**：终态编排可以是「内置大脑（MCP 客户端）同时调 Linear 官方 MCP 与本项目 MCP 工具」；自研 GraphQL 适配器仅在需要无大脑参与的全自动同步时启用。

## 后果

- M3 的 skill 与 M7 的 MCP server 是同一契约的两种壳，描述可复用
- M6 的内置 LLM 同样是契约的客户端，Core 不 import 任何 LLM 类型
- 接口演进以契约为锚：改操作签名 = 改契约，需同步所有壳
